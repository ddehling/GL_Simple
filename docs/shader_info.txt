# Shader Creation Guide: Depth + Alpha Blending System

## HARD RULES — non-negotiable, applies to every project shader

These rules exist because every shader regression we've shipped has been a violation
of one of them. Treat them as build-failures-in-spirit even if no CI enforces them.

1. **`glDepthFunc(GL_ALWAYS)` MUST NOT appear in any project shader file.**
   `GL_LESS` is the engine default; flipping to `ALWAYS` is the priority-based
   hack we're trying to retire. If you need to put something on top of everything
   else, give it a smaller `gl_Position.z`, not `GL_ALWAYS`.

2. **`glDepthMask(GL_FALSE)` IS required for translucent draws** so that
   multiple translucent layers stack visually (instead of the first-drawn
   blocking everything else via depth-write). Wrap the draw with
   `glDepthMask(GL_FALSE)` ... draw ... `glDepthMask(GL_TRUE)`. Depth-TEST
   stays on; only depth-WRITE is suppressed. This is standard translucent
   pipeline practice — do NOT confuse it with the priority-based hack in
   rule 1.

3. **Every fragment carries its own `gl_Position.z`.** Even fullscreen
   atmospheric effects get a fixed-but-unique z value from the realm's z-band
   table below. No two effects in the same realm share a z value (otherwise
   they depth-fight when one of them happens to have depth-write on).

4. **Straight alpha output only.** Fragment shaders write `vec4(rgb, alpha)`,
   never `vec4(rgb * alpha, alpha)`. The global blend is
   `GL_SRC_ALPHA / GL_ONE_MINUS_SRC_ALPHA`; pre-multiplied output gives doubly-
   attenuated colors. See "Alpha Output Rules" further down.

5. **No `render_priority`-driven layering.** Visual stacking is determined by
   each fragment's `gl_Position.z` (depth test) and the order effects happen
   to draw within the frame. The legacy `render_priority` field is treated as
   a batching hint only; do NOT rely on it to put one effect in front of
   another. If two effects need a specific stacking, give them appropriate z
   values from the z-band table.

6. **Never let a transparent layer punch through an opaque backdrop — never
   work around the depth + transparency pipeline.** A translucent effect that
   WRITES depth in front of an opaque backdrop carves that backdrop away
   wherever it draws, *even where it is fully transparent* (alpha 0), because
   depth-write is not gated by alpha. Real bug: daytime stars at z=0.90 stamped
   depth over the bartiki BART map (z 0.96-0.98, drawn after them) and showed
   as black spots in the map. The fix is to set the depth correctly, NOT to
   band-aid it with a `discard` on transparent fragments. In order of
   preference: (a) place the effect at a depth consistent with where it belongs
   in the scene — behind the backdrops it should sit behind; use a per-set
   depth when one z can't serve conflicting backdrops (bartiki stars sit at
   z=0.99 behind its map, while cyberpunk stars stay at z=0.90 in front of its
   0.95 sky); (b) translucent layers should set `glDepthMask(GL_FALSE)` (rule
   2) so they never write depth at all. Pick the depth; don't hack the pipeline.

If you need additive blending (bioluminescent glow, fire embers, etc.), wrap
the draw with `glBlendFunc(GL_SRC_ALPHA, GL_ONE)` + restore. Additive AND
glDepthMask(GL_FALSE) together is the standard particle-glow pattern.

## Pre-merge checklist (treat each item as required)

Before you commit a shader change, confirm:

- [ ] No `glDepthFunc(` or `glDepthMask(` calls appear in this file.
- [ ] Every `gl_Position = vec4(..., z, 1.0)` uses a z that is either:
      (a) per-vertex/per-particle (varying); OR
      (b) flat AND distinct from every other effect in the same realm per the
      z-band table.
- [ ] Fragment shader outputs `vec4(rgb, alpha)` — grep for `* alpha,` to find

- [ ] `render_priority` is set to something reasonable but is NOT being used to
      enforce visible layering.

## TL;DR — old pattern names (legacy, kept for non-ocean realms)

The two-pattern framing below predates the depth-band conversion. It's kept here
because realms that haven't been migrated still use Pattern B. For ocean and any
new realm, follow the HARD RULES above instead.

### Pattern A — 3D-style geometry (rain drops, snowflakes, leaves, particles)
- Each fragment has its OWN depth (gl_Position.z varies per object)
- Wants depth occlusion: a particle in front should hide a particle behind
- Use the standard pattern: vertex shader writes `gl_Position = vec4(clipPos, depth, 1.0)`
- Do NOT touch glDepthFunc / glDepthMask
- Output `vec4(rgb, alpha)` with STRAIGHT alpha (NOT pre-multiplied)

### Pattern B — Fullscreen-quad atmospheric layers (legacy, non-ocean realms)
- Single fullscreen quad at a CONSTANT depth
- Layers compose via alpha blending in priority order, not depth occlusion
- Render order is determined by `self.render_priority` only — lower renders first (back)
- MUST disable depth in render(): `glDepthFunc(GL_ALWAYS) + glDepthMask(GL_FALSE)`,
  then restore `GL_LESS + GL_TRUE` on exit
- Output `vec4(rgb, alpha)` with STRAIGHT alpha (NOT pre-multiplied)

If your effect renders a single fullscreen quad in a non-ocean realm, you may
still use Pattern B until that realm is migrated. New ocean effects MUST use
the depth-based approach (HARD RULES above).
If you've ever written `vec4(color * alpha, alpha)` you have a pre-multiplied alpha
bug — see the Alpha Output Rules below.

## Alpha Output Rules (FUSED RULE — read before every shader)

The global blend function is `glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA)`:

```
result = src.rgb * src.alpha + dst.rgb * (1 - src.alpha)
```

This is **straight alpha blending**, NOT pre-multiplied. So your fragment shader
MUST output:

```glsl
fragColor = vec4(rgb, alpha);          // CORRECT
```

NOT:
```glsl
fragColor = vec4(rgb * alpha, alpha);  // WRONG — color is doubly attenuated
fragColor = vec4(rgb * alpha, alpha * 0.85);  // WRONG — also pre-multiplied
```

Symptom of pre-multiplied output: colors look dim or muddy when they should look
saturated; the effect appears "weak" even at high alpha.

## Render Priority and Layer Order (FUSED RULE)

`self.render_priority` controls draw order:
- LOWER priority renders FIRST (background)
- HIGHER priority renders LAST (foreground)

For fullscreen-quad atmospheric layers (Pattern B), priority IS the layering —
nothing else can re-order them since none write depth.

## Wiring a New Uniform — DON'T MISS A STEP

To add a new uniform driven by a weather param, ALL FOUR steps are required:

1. **Declare in fragment shader**: `uniform float u_my_param;`
2. **Add field to effect class** (`__init__`): `self.my_param = 0.0`
3. **Read from outstate in wrapper**: `eff.my_param = float(outstate.get('my_param', 0.0))`
4. **Pass to GL in render()**: `glUniform1f(glGetUniformLocation(self.shader, "u_my_param"), self.my_param)`

If you forget step 3 (very easy — it's in the wrapper not the class), the uniform
stays at the class default forever and the param does nothing. Symptom: changing
the param in weather presets has no visible effect.

For the param to also flow from weather presets through to outstate:
5. **Add to the project's `OUTSTATE_PUBLISH` table** (in `projects/<id>/weather_params.py`): include `"my_param": 0.0` (or a `lambda params, season, t: ...` for derived values). The engine (`lib/weather_state.py get_state_output`) only publishes the generic core — fog/wind/rain/stars/ambient_light — so a realm param that isn't in the project table NEVER reaches outstate.
6. **Add to `lib/weather_params.py` `PARAMETER_DEFINITIONS`**: type/step entry
7. **Add to `lib/weather_params.py` `DEFAULT_WEATHER_PARAMS`**: default value
8. **Add to the relevant set's `allowed_parameters`**: so it's editable in that set

## Time-based Animation — NEVER multiply u_time by a varying uniform

This is the single most common cause of single-frame jumps, rain falling
upward, snow slowing-then-reversing, etc. — see git log around the
`weather state transition rain` regression.

### The bug

```glsl
// BUG — drift rate is coupled to a uniform that interpolates
uniform float u_time;
uniform float u_wind;
...
float drift = u_time * u_wind * 0.04;
```

Looks innocent. But `u_wind` interpolates during weather state transitions
while `u_time` is a large accumulated value. The wall-clock derivative is:

```
d(u_time * u_wind)/dt = u_wind                       (the desired motion)
                      + u_time * d(u_wind)/dt        (unwanted; scales with
                                                      how long the program
                                                      has been running)
```

After a few minutes of runtime the unwanted term dominates the first. While
`u_wind` is decreasing, the total derivative goes NEGATIVE — particles drift
backward even though wind is only slowing down, not reversing. Visual: rain
sliding upward during transitions, snow snapping the wrong way, fog that
animates fine then jerks when the state changes.

The same hazard applies to `fract(u_time / period)` and `floor(u_time * rate)`
whenever `period` / `rate` is itself a varying uniform.

### The fix — integrate phase on the CPU

Maintain a `_phase` accumulator on the effect class. Each frame, integrate it
using the CURRENT rate value:

```python
class MyEffect(ShaderEffect):
    def __init__(self, viewport):
        ...
        self._wind_phase = 0.0   # integrated dt * current_wind
        self.wind = 0.0

    def update(self, dt: float, state: Dict):
        self._time += dt
        self._wind_phase += dt * self.wind          # ← the fix

    def render(self, state: Dict):
        ...
        glUniform1f(glGetUniformLocation(self.shader, "u_wind_phase"),
                    self._wind_phase)
```

```glsl
// FIXED — phase is monotonic by construction
uniform float u_wind_phase;
...
float drift = u_wind_phase * 0.04;
```

`u_wind_phase` advances quickly when `wind` is high, slowly when `wind` is low,
never backward — regardless of how the underlying rate interpolates.

If you need rate AND wind both integrated, use one phase per axis:
`_rate_phase`, `_wind_phase`. Don't try to combine them into one uniform —
they advance at independent rates.

### Variant — fract / floor of `u_time / period` with varying period

A related form: drips, pulses, or other event-cadence shaders that compute
`fract(u_time / spawn_period)` where `spawn_period` is rate-coupled. The same
math applies — when `spawn_period` interpolates, the fract winds backward and
the events appear to drift in reverse.

Two acceptable fixes:

1. **Lock the period to a constant** and modulate intensity instead via a
   per-event visibility gate keyed off the rate uniform. Example pattern from
   `rain_on_leaves.py`:

   ```glsl
   const float spawn_period = 0.7;   // fixed
   ...
   float visibility = step(1.0 - clamp(u_rain * 1.4, 0.0, 1.0),
                           hash(vec2(col, drip_idx)));
   if (visibility < 0.5) continue;
   ```

2. **Integrate an event-phase on the CPU**: `self._event_phase += dt * rate`
   per frame, then use it as `floor(u_event_phase)` / `fract(u_event_phase)`
   in the shader.

### Quick check before merging a shader

Grep your shader for `u_time *` and `u_time /`. EVERY hit must be one of:

1. **Literal constant**: `u_time * 2.0`, `u_time * 0.06` — fine, frequency is
   fixed.
2. **Per-particle constant**: `u_time * pulseSpeed` where `pulseSpeed`
   is derived from `hash(particleId)` and never changes — fine.
3. **A uniform that never changes after init** — fine.

If `u_time` is multiplied or divided by anything driven from weather params
(`u_wind`, `u_rate`, `u_density`, `u_intensity`, `u_season`, audio uniforms,
etc.), you have the bug. Convert to an integrated phase.

## Wrapper Default Values — keep them at zero

In your shader wrapper, when reading from `outstate`, the FALLBACK value should be
`0.0` (or otherwise "invisible"), not a moderate value:

```python
# CORRECT — if the param isn't set on the active state, the effect is invisible
eff.density = float(outstate.get('canopy_density', 0.0))

# WRONG — effect renders at moderate density even when state didn't intend it
eff.density = float(outstate.get('canopy_density', 0.5))
```

The reasoning: misconfiguration should fail visibly to NOTHING, not to a partial
effect that's hard to debug.

## Overview

The shader renderer uses **simultaneous depth testing and alpha blending** to create a proper 3D layering system where transparent objects correctly occlude each other based on depth.

## Global OpenGL State (Always Active)

Set once in create_window() - NEVER toggle in individual shaders:
- glEnable(GL_DEPTH_TEST)           # Depth testing always on
- glDepthMask(GL_TRUE)              # Allow depth writes
- glEnable(GL_BLEND)                # Alpha blending always on
- glBlendFunc(GL_SRC_ALPHA, GL_ONE_MINUS_SRC_ALPHA)  # Standard alpha blend

This means: Every fragment is depth-tested AND alpha-blended. The GPU checks "is this in front?" (depth test) then "how transparent is it?" (alpha blend).

## Depth Buffer Setup

Each viewport has:
- Color texture (RGBA) for final image
- Depth texture (GL_DEPTH_COMPONENT16) for z-ordering
- Both cleared every frame: glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT)

## Required Shader Structure

### Vertex Shader Requirements

You MUST output proper depth values to gl_Position.z:

```glsl
#version 310 es
precision highp float;

layout(location = 0) in vec2 position;
layout(location = 1) in vec3 offset;    // x, y, z (your depth coordinate)

uniform vec2 resolution;

void main() {
    vec2 pos = position * scale + offset.xy;
    vec2 clipPos = (pos / resolution) * 2.0 - 1.0;
    clipPos.y = -clipPos.y;  // Flip Y for screen coords
    
        // CRITICAL: Map your z-coordinate where z=0 is near, z=100 is far
    float depth = offset.z / 100.0;  // Standard range: z = 0-100
    depth = clamp(depth, 0.0, 1.0);
    
    gl_Position = vec4(clipPos, depth, 1.0);
}
```

### Fragment Shader Requirements

You MUST output RGBA with meaningful alpha:

```glsl
#version 310 es
precision highp float;

out vec4 outColor;

void main() {
    vec3 color = vec3(1.0, 0.5, 0.0);
    float alpha = 0.7;
    outColor = vec4(color, alpha);
}
```

## Standard Depth Coordinate System

z = 0     → Very near → depth = 0.0 → Drawn last (in front)
z = 50    → Mid depth → depth = 0.5 → Middle
z = 100   → Far away  → depth = 1.0 → Drawn first (behind)

Mapping formula: depth = z / 100.0 where z ∈ [0, 100]

## How It Works

1. Rendering Order: Effects render in order added to viewport.effects
2. Fragment Processing: For each fragment:
   - GPU checks: "Is this fragment's depth closer than what's in the depth buffer?"
   - If YES: Continue to alpha blend
   - If NO: Discard fragment (it's behind something)
3. Alpha Blending: Surviving fragments blend with existing color using alpha
4. Depth Write: Opaque or semi-transparent fragments update the depth buffer

## What You Get

✅ Objects at different depths correctly occlude each other
✅ Transparency works naturally (alpha blending)
✅ No sorting needed (GPU handles it via depth buffer)
✅ Rain drops can be in front of AND behind circles depending on z-value

## Horizontal Wrapping Requirement

**All shaders MUST be continuous across the left/right boundary.**

For LED displays that wrap horizontally (like cylindrical installations), objects must appear seamless when crossing screen edges.

### Implementation:

1. **Wrap Margin**: Define a margin (e.g., 50 pixels) from each edge
2. **Detect Edge Objects**: Identify objects within wrap_margin of left or right edge
3. **Duplicate Objects**: Create temporary duplicates on the opposite side
4. **Render Both**: Draw both original and duplicate in same render call

### Example (from rain.py):

```python
self.wrap_margin = 50  # Should be larger than largest object size

# In render():
left_edge_mask = self.positions[:, 0] < self.wrap_margin
right_edge_mask = self.positions[:, 0] > (self.viewport.width - self.wrap_margin)

# Objects near left edge need duplicates on right
if np.any(left_edge_mask):
    left_indices = np.where(left_edge_mask)[0]
    duplicate_pos = self.positions[left_indices].copy()
    duplicate_pos[:, 0] += self.viewport.width  # Shift to right side
    # Add to render list

# Objects near right edge need duplicates on left
if np.any(right_edge_mask):
    right_indices = np.where(right_edge_mask)[0]
    duplicate_pos = self.positions[right_indices].copy()
    duplicate_pos[:, 0] -= self.viewport.width  # Shift to left side
    # Add to render list

# Render all: originals + duplicates in one draw call
```

### Key Points:

✅ Wrap margin should exceed your largest object size
✅ Duplicates share ALL attributes (color, depth, size, etc.)
✅ Only X position is modified for duplicates
✅ Render originals and duplicates together for efficiency
✅ No gaps or pop-in at screen edges

## Post-Processing / Atmospheric Layer Pattern (Pattern B)

**Use this for fullscreen-quad effects:** sky/glow backdrops, atmospheric tints,
particle fields rendered procedurally in a fragment shader, leaf canopies, etc.

These render AFTER all 3D geometry (or interleaved with it via priority) and
apply screen-space color modifications. They are layered via render_priority
and alpha blending — NOT via depth occlusion.

### What Makes Them Different:

✅ Render a fullscreen quad covering the entire screen
✅ Read from framebuffer textures (color and/or depth)
✅ Don't participate in 3D depth ordering
✅ Run as final pass in the render pipeline

### Depth Handling for Post-Process:

**Option 1: Use glDepthFunc (Recommended)**

```python
def render(self, state: Dict):
    # Post-process exception: Always pass depth test without toggling
    glDepthFunc(GL_ALWAYS)  # Always pass depth test (render in front)
    glDepthMask(GL_FALSE)   # Don't write to depth buffer
    
    glUseProgram(self.shader)
    # ... render fullscreen quad ...
    glUseProgram(0)
    
    # Restore default state
    glDepthFunc(GL_LESS)
    glDepthMask(GL_TRUE)
```

**Option 2: Toggle depth test (Legacy)**

```python
def render(self, state: Dict):
    glDisable(GL_DEPTH_TEST)  # Allowed for post-process only
    
    glUseProgram(self.shader)
    # ... render fullscreen quad ...
    glUseProgram(0)
    
    glEnable(GL_DEPTH_TEST)  # Re-enable for next frame
```

### Post-Process Examples:

- **ShaderFog**: Depth-based atmospheric fog with blur
- **ShaderBloom**: Glow effect for bright areas
- **ShaderColorGrade**: Color correction and tone mapping
- **ShaderVignette**: Darkening at screen edges

### Important:

✅ Post-process effects CAN modify depth state
✅ They MUST restore state after rendering
✅ They run AFTER all 3D geometry is complete
❌ They should NOT write to the depth buffer
❌ They should NOT occlude 3D objects

## What NOT To Do

❌ Never call glEnable/Disable(GL_DEPTH_TEST) in **3D geometry shaders**
❌ Never call glDepthMask(GL_FALSE) in 3D shaders (prevents proper occlusion)
❌ Never omit the depth value in gl_Position.z for 3D objects
❌ Never use projection matrices that conflict with the 0-1 depth range
❌ Never allow objects to disappear at screen edges (breaks wrapping continuity)

**Exception**: Post-processing effects (rendering fullscreen quads after all geometry) may modify depth state as shown above.

## Event System Integration

**All shader effects should include an event wrapper function for use with EventScheduler.**

This allows effects to be scheduled, started, stopped, and cleaned up automatically.

### Event Wrapper Function Pattern:

```python
def shader_myeffect(state, outstate, param1=default1, param2=default2):
    """
    Shader-based effect compatible with EventScheduler
    
    Usage:
        scheduler.schedule_event(0, 60, shader_myeffect, param1=value, frame_id=0)
    
    Args:
        state: Event state dict (contains start_time, elapsed_time, count, frame_id)
        outstate: Global state dict (from EventScheduler)
        param1: Your custom parameter
        param2: Your custom parameter
    """
    # 1. Get viewport from renderer
    frame_id = state.get('frame_id', 0)
    shader_renderer = outstate.get('shader_renderer')
    
    if shader_renderer is None:
        print("WARNING: shader_renderer not found in state!")
        return
    
    viewport = shader_renderer.get_viewport(frame_id)
    if viewport is None:
        print(f"WARNING: viewport {frame_id} not found!")
        return
    
    # 2. Initialize effect on first call (count == 0)
    if state['count'] == 0:
        print(f"Initializing myeffect for frame {frame_id}")
        
        try:
            effect = viewport.add_effect(
                MyEffect,
                param1=param1,
                param2=param2
            )
            state['effect'] = effect
            print(f"✓ Initialized shader myeffect for frame {frame_id}")
        except Exception as e:
            print(f"✗ Failed to initialize myeffect: {e}")
            import traceback
            traceback.print_exc()
            return
    
    # 3. (Optional) Update effect from global state
    if 'effect' in state:
        state['effect'].some_param = outstate.get('some_global_param', param1)
    
    # 4. Cleanup on close event (count == -1)
    if state['count'] == -1:
        if 'effect' in state:
            print(f"Cleaning up myeffect for frame {frame_id}")
            viewport.effects.remove(state['effect'])
            state['effect'].cleanup()
            print(f"✓ Cleaned up shader myeffect for frame {frame_id}")
```

### Event Wrapper Requirements:

✅ **Function signature**: `def shader_name(state, outstate, **custom_params)`
✅ **Initialize on first call**: Check `state['count'] == 0`
✅ **Store effect in state**: `state['effect'] = effect` for later access
✅ **Handle cleanup**: Check `state['count'] == -1` and call `cleanup()`
✅ **Error handling**: Wrap initialization in try/except with traceback
✅ **Logging**: Print initialization and cleanup messages
✅ **Global state updates**: Optionally read from `outstate` for dynamic parameters

### Key Points:

- `state` is per-event, persists across calls
- `outstate` is global, shared across all events
- `state['count']` tracks event lifecycle: 0 (init), N>0 (running), -1 (cleanup)
- `state['elapsed_time']` provides time since event started (in seconds)
- `state['duration']` provides total event duration (if scheduled with duration)
- `frame_id` identifies which viewport to use
- Effect remains active between calls (updates/renders automatically)
- Always remove from `viewport.effects` and call `cleanup()` on close

### Fade In/Out Pattern:

For smooth transitions, implement fade in/out based on `elapsed_time`:

```python
def shader_myeffect(state, outstate, param1=1.0):
    # ... initialization code ...
    
    # Update fade factor every frame (after initialization)
    if 'effect' in state:
        elapsed_time = state['elapsed_time']
        total_duration = state.get('duration', 60)  # Default 60s if not set
        fade_duration = 10.0  # Fade in/out over 10 seconds
        
        # Calculate fade factor (0.0 to 1.0)
        if elapsed_time < fade_duration:
            # Fade in during first N seconds
            fade_factor = elapsed_time / fade_duration
        elif elapsed_time > (total_duration - fade_duration):
            # Fade out during last N seconds
            fade_factor = (total_duration - elapsed_time) / fade_duration
        else:
            # Full opacity in the middle
            fade_factor = 1.0
        
        # Update effect's fade factor (clip to 0-1 range)
        state['effect'].fade_factor = np.clip(fade_factor, 0, 1)
    
    # ... cleanup code ...
```

**In your effect class:**

```python
class MyEffect(ShaderEffect):
    def __init__(self, viewport, param1: float = 1.0):
        super().__init__(viewport)
        self.fade_factor = 0.0  # Start fully transparent
        # ... rest of init ...
    
    def render(self, state: Dict):
        glUseProgram(self.shader)
        
        # Pass fade factor to shader
        fade_loc = glGetUniformLocation(self.shader, "fadeAlpha")
        if fade_loc != -1:
            glUniform1f(fade_loc, self.fade_factor)
        
        # ... rest of render ...
```

**In your fragment shader:**

```glsl
uniform float fadeAlpha;

void main() {
    vec3 color = vec3(1.0, 0.5, 0.0);
    float alpha = 0.8;
    
    // Apply fade factor to final alpha
    alpha *= fadeAlpha;
    
    outColor = vec4(color, alpha);
}
```

**Benefits:**
- ✅ Smooth fade in at start (no sudden appearance)
- ✅ Smooth fade out at end (no sudden disappearance)
- ✅ Automatically uses event duration from scheduler
- ✅ Adjustable fade duration (independent of total duration)
- ✅ Works with any effect type

## Shader Effect Initialization Flow

**CRITICAL: Understanding the initialization sequence**

The shader system has a specific initialization order that MUST be followed:

```
1. __init__(viewport, **params)    # Your constructor - set parameters, initialize data
2. add_effect() creates effect     # Called by viewport.add_effect(EffectClass, **params)
3. effect.init()                   # Called automatically by add_effect()
   ├─> compile_shader()            # YOU MUST IMPLEMENT THIS
   └─> setup_buffers()             # Called after shader is compiled
```

### Key Rules:

✅ **DO** initialize data structures in `__init__`
✅ **DO** implement `compile_shader()` method to compile vertex/fragment shaders
✅ **DO** implement `setup_buffers()` to create VAO/VBO/EBO (called after shader compiles)
❌ **DON'T** call `setup_buffers()` in `__init__` (shader doesn't exist yet!)
❌ **DON'T** call `init()` yourself (add_effect() does this automatically)
❌ **DON'T** try to use `self.shader` before `init()` is called

### The compile_shader() Method

Every shader effect MUST implement this method:

```python
def compile_shader(self):
    """Compile and link shaders"""
    vertex_shader = self.get_vertex_shader()
    fragment_shader = self.get_fragment_shader()
    
    try:
        vert = shaders.compileShader(vertex_shader, GL_VERTEX_SHADER)
        frag = shaders.compileShader(fragment_shader, GL_FRAGMENT_SHADER)
        shader = shaders.compileProgram(vert, frag)
        return shader
    except Exception as e:
        print(f"Shader compilation error: {e}")
        raise
```

This method is called by the base class's `init()` and must return the compiled shader program.

## Auto-Discovery and Imports

The shader effects package uses automatic discovery. When you create a new shader file:

✅ Name shader wrapper functions with `shader_` prefix: `shader_myeffect`
✅ Name effect classes with `Effect` suffix: `MyEffect`
✅ Both will be automatically imported by `__init__.py`
✅ No need to manually edit `__init__.py`!

The auto-discovery system:
```python
# In __init__.py (already implemented):
# - Scans all .py files in shader_effects/
# - Imports functions starting with 'shader_'
# - Imports classes ending with 'Effect'
# - Makes them available globally
```

This means you just create `myeffect.py` with `shader_myeffect()` and `MyEffect` class,
and they're immediately available to the rest of the system!

## Summary

The renderer maintains global depth testing + alpha blending state. Your shader just needs to:
1. Implement `compile_shader()` method (required!)
2. Write correct depth to gl_Position.z (z=0 near/depth=0.0, z=100 far/depth=1.0)
3. Output RGBA with proper alpha in fragment shader
4. Never call `setup_buffers()` in `__init__` (init() does this after compilation)
5. Never touch depth test or blend state
6. Implement horizontal wrapping by duplicating edge objects

That's it! The system handles initialization, shader compilation, and 3D ordering automatically. 🎯

## Additional Notes

- The renderer uses OpenGL ES 3.1 for compatibility with Raspberry Pi
- All shaders must use #version 310 es and precision highp float
- Viewports have separate framebuffers for LED output at native resolution
- Window display (viewport 0 only) can be different size from framebuffer
- Effects are rendered twice: once to framebuffer (LED), once to window (if not headless)
